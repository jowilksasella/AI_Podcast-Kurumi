# 局部修订与最小检查

## 继续

读 manifest、cache、日志和现有进度，确认是否仍有模型进程运行。正常段落与有效证据复用；异常先定位重复、漏句、读音或角色错配，只针对失败段落重做。

保持同一个冻结原始配置。旧产物带有不同演员、空情绪映射或实验参数时，不能称为原始模式有效缓存。

## 开场修订

新铺垫须连得上原第一句，而不是把两句欢迎语硬粘在突兀开场前。

    python -m kurumi_podcast patch-opening opening.json --base outputs/episode --config config.local.json --out outputs/intro-v2 --replace-until 6.215

replace-until 默认 0（前置）；替换只选实际已有发言边界，不照抄示例秒数。新开场与正常正文母带拼接，章节/字幕/主讲比例和前 60 秒试听更新，旧版保留。opening 使用配方中的独立参数，不声称与原 41 秒逐轮试听相同。

## 针对性检查

| 检查 | 能发现的具体失败 | 不证明什么 |
|---|---|---|
| core 校验 + text 总字数/最长轮/主讲占比 | 超长预览、长轮、缺铺垫标记、主讲退成配角 | 实际时长、声音自然度 |
| bind-original / doctor | 原始槽位缺失、资产身份不符、空情绪映射、演员/参数/环境漂移 | 新文本听感或历史波形一致 |
| 实际时长与 manifest 有效发言占比 | 短样不在 30–60 秒、全篇久留美不足 60% | 聊天有趣或像真人 |
| 相关片段播放/必要时 ASR、波形检查 | 漏读、重复、数值或买卖动作错误、明显削波/截断 | ASR 正确、无削波、文件成功不等于自然 |
| 实际短试听与用户反馈 | 声线区分、语气与内容相称、接话松弛、双方贡献、念稿感 | 配方一致也不能直接标记获认可 |

写作检查要读台词：铺垫是否建立场景，有没有好奇/轻玩笑，搭档是否真的贡献内容，主讲是否推进解释。不靠角色轮流出现或塞满“嗯、啊”评分。

声音检查要听新增/变化片段：固定 JA 音色是否区分清楚，ZH 情绪是否有聊天的好奇与反应，停顿/轻玩笑是否落在内容上，而不是每句重新开播或整段讲课。没有音频听辨能力时标为“听感未验证，待用户试听”，不声称亲耳听过。

原始模式参数保持不变；预览时长不合适优先改少量台词。有效 alpha=1 或某种情绪丢失时先查独立 emotion_audio 是否实际传入，不凭配置上 `0.5` 断言成功。

## 问题词与修复边界

只抽查与本次内容相关的失败：数字、买入/卖出、正负号、漏句/重复、角色错配、开头衔接。ASR 本身也会错，同音字不自动等于语义错误；关键动作确实混淆时，改明确动作或仅修问题处的 tts_text。

停顿不是每轮统一加静音；保留自然呼吸，不以变速/升调把普通声音包装成目标角色。修完只重查受影响片段。

不把新短样生成完当成已经确认，不用批准参数替代用户反馈。不做普通保存/提交的整树哈希、不反复跑已通过且输入未变的整集检查；证据够用就交付。
