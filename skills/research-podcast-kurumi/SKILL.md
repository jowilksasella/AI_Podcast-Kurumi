# 久留美主讲研究播客

根仓库 URL 是制作入口，默认读取当前 main 的恢复工作流 `original-chat-20261002` 和已绑定、冻结的本地配置；不按 latest release 自动选择 v0.2.0。只有复核旧例才沿用 GEX，新任务的内容以本次资料为准。

## 原始模式

- 久留美主讲、萌智子搭档；文字量目标 65–75%，完整音频有效发言至少 60%。搭档有解释、追问、补充或校对贡献，不固定成老师/学生。
- 复用已确认的本地 IndexTTS 2.5：独立日语演员音色 + 原始中文 delivery 情绪库。执行前读 [runtime.md](references/runtime.md)，保持冻结配置，不清空情绪映射、不自动换演员/搭档/采样参数/引擎/版本，不切 Edge。
- 原始素材缺失或不匹配时，报具体槽位和原因；不制造替代情绪、重剪新演员样本或降级普通女声。库可在本地准备一次，声音不上传。
- 角色分工、公开演员样本、独立情绪参考、角色专用模型分别标明；成品是 AI 生成普通话，不是演员本人录音。
- 用户明确要求其他风格时另建配置与短样，原始配置保留；不把独立实验叫作原始恢复。换搭档或统一情绪映射用 runtime 中的 `variant` 配置，继承原始设置与执行方式，不另写外部渲染脚本。
- 全部台词用标准普通话简体；研究要融入讨论（作者、平台/期刊、日期、发现），口播不念页码/DOI，也不念制作幕后。完整版不设时长上限。细则见 writing.md。
- 逐句好/坏反馈用来选定整集配置，不逐句重录或挑 seed；见 revisions.md。
- 用户要求用动画对白做音色时，按 runtime 的“动画对白声线素材”流程在本机准备：去 BGM、按声线排候选、剪核对视频、由用户确认；只把确认过的片段用于 variant 短样。参考片段先用 `compress-pauses` 把句内停顿压到 ≤0.4 秒，否则引擎会学出长静音、漏读。
- **动画音色定稿（GEX，2026-10-22 用户认可）**：久留美与萌智子都用动画对白音色，参考已提交在 `voices/anime-20261022/`，配置模板 `examples/anime-cast.variant.json`（中文情绪仍用原始库）。用户要动画音色或做 Shorts 时默认用它；原始演员配置照旧冻结保留。
- 用户要做短视频时，按 [shorts.md](references/shorts.md) 拆成每集一分钟以内的独立系列：第一句即钩子、不自我介绍，`split-series` → 样片 → `render-series` → `qa` / `asr-check` → `source-map` 交给视频 Agent。

## 阶段与完成标准

### 1. 取材与环境

遵循宿主的 research-first 要求，分别查官方资料与 GitHub 可复用实现后实施。读本次原文的关键图表，记录页码、年代、单位、假设与结果。复用已有模型与本地配置；需要绑定或迁移时读 runtime，根因背景见 [恢复与迁移](../../docs/original-chat-restoration.md)（仅单装 Skill 时需在完整仓库读取）。

完成标准：内容可追溯；两位角色、非空中文情绪映射和原始素材身份对应明确；可执行配置已绑定，结构模板不能当运行配置。

### 2. 写短样

先读 [writing.md](references/writing.md)。前两句交代人物和怪现象，再用好奇、轻吐槽和实质解释自然接入。约 220–270 字、每轮约 50 字以内，总量不超过 360 字；不为了轮流说话而硬插问题。唯一规范写作示例是完整仓库的 `examples/preview.json`。

完成标准：现有 core 校验通过；主讲有理解与推进，搭档有贡献；30–60 秒只是生成目标，未渲染不承诺时长。

### 3. 生成与试听

按 runtime 使用冻结配置，先校验/doctor，再只生成短样。新音频检查读 [revisions.md](references/revisions.md)：结构、实际时长、关键词和声音自然度分开检查。没有听辨能力时准确注明未验证听感，不把 ASR、无削波或文件成功当作“自然/获认可”。

完成标准：交付可播放的实际 30–60 秒样片及文本；来源与身份准确；停在预览等待用户反馈。配方恢复不保证任意新文本逐位相同或自动好听。

### 4. 完整版

仅在用户明确认可这次短样并要求开始后推进。沿用获认可的演员、中文情绪、解码与写作选择，按本次原文写全稿：先列覆盖计划（保留/扩展/省略及理由），不以时长为目标，检查信息覆盖和主讲比例。保持自然短轮、缓存与恢复；生成音频、文字稿、章节和字幕初稿，再用 `qa` 找该听的轮次、`package-chapters` 切分章 MP3。

完成标准：完整音频可播放；久留美有效发言至少 60%；关键数字、动作、正负号与来源一致；`qa` 无 `long_internal_pause`，`asr-check` 无漏句（并列买卖等列为待听点）；不以 `--approved-preview` 参数代替实际确认。

### 4b. 一分钟系列（Shorts 用）

用户要短视频时，在资料已核实后把内容拆成独立的一分钟集，细则见 [shorts.md](references/shorts.md)。先渲染一集样片（通常 ep01）给用户听，认可写法与长度后再 `render-series` 批量；每集检查同完整版。交付每集音频、字幕、manifest 时间码与 `source-map/`（逐句对应主资料的页、段、图），视频由 AI_Animation-Kurumi 的 `kurumi-shorts` 制作。

完成标准：每集 30–60 秒（目标约 55 秒）、钩子 3–5 秒；全部台词有来源 ID；未听过的不标为认可。

### 5. 修订或继续

读已有计划、缓存和运行状态；继续正常进度，不重启整集。只改开头/一句时按 revisions 重做受影响部分，保持冻结声音配置和正常正文母带。开场要与旧第一句连得上，章节/字幕随之更新。

完成标准：具体修改处和新预览可交付；未变部分复用；不把这次还未听过的新声音标为获认可。

## 交付

先给可播放音频，再给稿件、章节与字幕；本地链接使用宿主支持的绝对路径。本仓库不做视频、人物动画、自动发布或训练。仓库不提交真实本机路径、本地配置、PDF、模型、密钥或登录态；用户认可的动画音色参考（`voices/`）和展示成品（`gallery/`）按用户决定提交，每次 commit/push 仍需用户同意。
